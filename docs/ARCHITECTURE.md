# FileBack 架构

## 设计目标

FileBack 是一个小型单 crate 桌面应用。架构借鉴 Zed 的领域拆分和平台隔离思路，但不引入多 crate workspace，以降低构建与维护成本。

核心原则：

1. 源镜像和源物理盘只读。
2. 扫描与恢复分离，恢复需要用户选择和二次授权。
3. 默认拒绝非空恢复目录，并检查目标不位于源物理盘。
4. 界面不直接实现磁盘 carving。
5. 核心逻辑可以在不启用 GPUI 的情况下测试。

## 模块边界

```text
┌──────────────┐       ┌──────────────┐
│  src/main.rs │       │  src/cli.rs  │
│  GUI entry   │       │  CLI entry   │
└──────┬───────┘       └──────┬───────┘
       │                      │
       ▼                      ▼
┌──────────────┐       ┌─────────────────────────┐
│     app      │       │       public library    │
│ actions      │       │ device / recovery / ... │
│ state / view │       └─────────────────────────┘
└──────┬───────┘
       │
       ▼
┌──────────────┐     ┌──────────────┐
│    device    │────▶│   recovery   │
│ raw scan I/O │     │ models/image │
└──────┬───────┘     └──────▲───────┘
       │                    │
       ▼                    │
┌─────────────────────────────────┐
│             system              │
│ disk / privilege / status       │
└─────────────────────────────────┘
```

### `app`

- `actions.rs`：菜单、快捷键和动作转发。
- `state.rs`：磁盘选择、扫描、暂停/取消、候选选择与恢复状态。
- `view.rs`：GPUI 渲染，不承担底层业务规则。

### `device`

- 管理物理盘扫描线程、读取块、候选合并和恢复范围。
- 使用 `recovery` 的共享模型。
- 使用 `system` 的目标盘校验。
- `tests.rs` 使用普通文件模拟设备，不请求管理员权限。

### `recovery`

- `model.rs`：文件类型、七类文件分组、扫描选项、设备候选和报告 DTO。
- `format.rs`：共享签名定位、JPEG 帧头与扫描头校验、ZIP 中央目录分类、RIFF 长度和 ISO 媒体 atom 边界；不支持的结构保守回退或拒绝，不做完整解码。
- `preview.rs`：JPEG、PNG 缩略图和 Office 核心元数据；限制源大小、解码尺寸、内存和元数据读取量，单项失败不影响恢复。
- `mod.rs`：普通镜像映射、签名定位和恢复输出；输出按类别写入 `images/`、`documents/`、`spreadsheets/`、`presentations/`、`videos/`、`audio/` 或 `archives/`。
- 不依赖 GPUI，也不负责 macOS 管理员授权。

### `system`

- `disk.rs`：封装 `diskutil`、物理盘枚举、设备指纹和目标盘隔离检查；恢复子目录先通过 `statfs` 定位所属挂载卷，再交给 `diskutil` 查询物理盘。
- `privilege.rs`：在用户明确操作后安装受限助手，并管理私有扫描会话。
- `helper.rs`：通过 launchd 套接字按需启动助手，校验客户端签名、用户及会话路径，只处理固定扫描、当前页预览与恢复请求。实际读取原始磁盘的是已安装助手，因此它也需要用户明确授予“完全磁盘访问权限”。
- `status.rs`：读取 APFS 快照和 Time Machine 状态。
- `mod.rs`：仅声明子模块并导出稳定 API。

## 核心流程

### 物理盘扫描

```text
用户选择磁盘
  → 创建随机、0700 的 ScanSession 目录
  → GUI 后台任务
  → 首次明确操作后，经管理员确认安装 launchd 按需助手
  → 验证 FileBack 客户端签名与当前用户
  → fileback-cli scan-device
  → device 只读扫描（逐块检查暂停 / 取消）
  → 原子 JSON 进度 / 同步 JSONL 候选
  → GUI 增量读取并合并展示
```

进度与候选文件使用 `O_NOFOLLOW`，管理员助手通过文件描述符把协作文件属主交还给当前用户。扫描结束时报告记录源路径、容量和设备指纹，会话目录随后自动清理。

### 候选预览

```text
扫描完成或翻页
  → 仅选择当前页尚未缓存的最多 10 个候选
  → GUI 后台请求受限助手，再次校验源设备身份
  → fileback-cli preview-device
  → 按候选范围只读，单个源文件最多读取 64 MiB
  → 限制图片解码和 Office 元数据资源，返回小型 PNG 与可选标题
  → GUI 按扫描代次缓存；过期结果丢弃，预览失败不阻断恢复
```

预览不写恢复文件，也不把候选内容上传到外部服务。PDF、视频、音频和普通 ZIP 当前只显示类型占位。

### 选择性恢复

```text
用户分页勾选候选并选择另一块磁盘上的恢复位置
  → GUI 校验目标盘并规划尚不存在的独立子目录（此时尚不创建）
  → GUI 和 CLI 双重校验报告来源及目标盘
  → 用户再次明确确认后创建独立目录
  → 验证 FileBack 客户端签名
  → fileback-cli recover-device
  → 校验偏移和大小，并按文件类别创建输出子目录
  → 分类目录内的临时文件写入并同步
  → persist_noclobber 发布最终文件（ExFAT 使用独占占位后原子重命名）
  → 通过文件描述符逐个交接恢复文件属主（不递归 chown）
  → 返回恢复报告
```

## 错误与数据安全

- 库函数返回 `anyhow::Result`，入口负责呈现错误。
- 输出使用 `NamedTempFile` 和 `persist_noclobber`，失败不发布残缺文件，也不覆盖同名文件。
- 原始设备路径必须来自磁盘枚举结果，并通过 `/dev/rdiskN` 校验。
- `diskN` 只用于定位当前设备，不能作为报告身份；UUID／IORegistry ID 或受限的媒体信息回退用于跨阶段比对。
- 所有新风险点都应在 [安全政策](../SECURITY.md) 的边界内评估。

## 测试策略

- 单元测试与模块放在同一领域目录。
- 核心测试通过 `--no-default-features` 运行，避免 GPUI/Metal 成为必要依赖。
- 新测试优先覆盖边界、截断输入、伪造签名、并发控制和输出目录安全。
- 真实物理盘测试需要独立、可丢弃的测试设备，不能作为默认 CI 操作。

## 何时拆成多 crate

只有当模块需要独立发布、独立依赖图或明确编译隔离时，才考虑迁移到 Cargo workspace。文件数量或“看起来像大型项目”本身不是拆 crate 的理由。
